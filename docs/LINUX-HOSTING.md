# نصب کافی‌نت‌یار مستقل روی لینوکس

نسخهٔ ۴، همان رابط React پروژه را با بک‌اند داخلی و دیتابیس SQLite اجرا می‌کند. هیچ حساب، کلید، SDK، اتصال WebSocket یا درخواست شبکه‌ای به Convex برای کار برنامه لازم نیست. ورود، رمزها، حسابداری و انبار، نرخ‌های اختصاصی، بانک سامانه‌ها، خبرها، پشتیبانی و گفت‌وگوهای دستیار در همین بک‌اند ذخیره می‌شوند.

## انتخاب هاست

**Node.js 24، فضای دیسک ماندگار و امکان اجرای یک برنامهٔ Node.js لازم است.** این بسته روی هاست دارای Node.js، cPanel/DirectAdmin دارای Node.js مناسب، یا سرور لینوکس اجرا می‌شود. هنگام خرید همین سه قابلیت را از میزبان بپرس. به MySQL یا نصب بستهٔ جانبی در زمان اجرا نیاز ندارد. مسیر برنامه را خارج از `public_html` و پوشهٔ عمومی وب قرار بده؛ دامنه یا ساب‌دامنه را به برنامهٔ Node متصل کن.

## نصب بستهٔ آماده

فایل `cafenetyar-linux-4.0.0.zip` را در پوشهٔ خصوصی برنامه باز کن. فایل‌های سرور، رابط، migrationها، راهنمای فارسی و تنظیمات نمونه داخل بسته‌اند. بسته هیچ دیتابیس شخصی، رمز یا کلید واقعی ندارد.

1. در بخش Node.js هاست، نسخهٔ ۲۴ و پوشهٔ برنامه را انتخاب کن. فایل شروع در پنل‌هایی که فایل CommonJS می‌خواهند `app.cjs` است؛ اجرای مستقیم با `npm start` نیز پشتیبانی می‌شود.
2. متغیرهای زیر را در پنل هاست تنظیم کن، یا `.env.example` را به `.env` کپی و تکمیل کن:

   ```dotenv
   NODE_ENV=production
   PUBLIC_ORIGIN=https://your-domain.example
   DB_FILE=./data/cafenetyar.sqlite
   HOST=127.0.0.1
   PORT=3000
   AUTH_PASSWORD_ITERATIONS=600000
   ```

   `PUBLIC_ORIGIN` باید مبدأ واقعی HTTPS دامنه، بدون مسیر اضافه باشد. اگر میزبان `PORT` تعیین می‌کند، مقدار میزبان را نگه دار. پشت Nginx محلی می‌توان `TRUST_PROXY=1` را تنظیم کرد. فایل نمونهٔ Nginx و سرویس systemd در بسته موجود است.
3. برنامه را Start/Restart کن. schema به‌صورت افزایشی روی SQLite ساخته می‌شود.
4. برای اولین مالک به `https://your-domain.example/install` برو. کد راه‌اندازی از فایل خصوصی `data/setup-token` کنار فایل دیتابیس قابل خواندن است؛ آن را فقط در همان صفحهٔ هاست خودت وارد کن. اگر `SETUP_TOKEN` از قبل در متغیرهای هاست تنظیم شده، همان مقدار استفاده می‌شود. نام، شماره، نام کاربری و رمز مالک را خودت تعیین کن. کد بازیابی نمایش‌داده‌شده را امن نگه دار. پس از ساخت مالک، این مسیر ساخت مالک بسته می‌شود.
5. از `/auth` وارد شو و سپس `/manage` را باز کن. تأیید دومرحله‌ای پنل مالک را تنظیم کن. حساب مشتریان فقط از «حساب‌های ورود سایت» توسط مالک ساخته می‌شود؛ ثبت‌نام عمومی بسته است.

### راه‌اندازی از ترمینال

پس از تنظیم `.env`، این دستور جایگزین نصب وب است؛ رمز هنگام تایپ نمایش داده نمی‌شود:

```bash
npm run owner:create
npm start
```

این دستور می‌تواند رمز مالک موجود را نیز با دسترسی مستقیم به همان فایل دیتابیس بازتنظیم کند. حساب مالک دیگری با شمارهٔ متفاوت جایگزین نمی‌شود. وب‌سایت هیچ رمز پیش‌فرض یا مسیر عمومی بازنشانی مالک ندارد.

## انتقال از میزبانی فعلی

1. در پنل فعلی `/manage`، «انتقال و پشتیبان‌گیری» را باز کن و ورود مستقل مالک را تنظیم کن. اگر فضای مالی قبلی نمایش داده می‌شود، همان فضای مربوط را انتخاب کن. شناسه‌ها، موجودی و اسناد آن فضا تغییر نمی‌کنند. انتقال از یک فضای فعلیِ دارای داده به فضای دیگر خودکار انجام نمی‌شود.
2. «دریافت پشتیبان JSON برای انتقال» را بزن. فایل شامل کاربران، هش رمزها، تنظیمات دومرحله‌ای، محتوا و داده‌های مالی ذخیره‌شده در این سایت است؛ آن را خصوصی نگه دار.
3. روی هاست مقصد، **پیش از ساخت مالک تازه** و در دیتابیس خالی، فایل را وارد کن:

   ```bash
   npm run restore -- /private/path/cafenetyar-backup.json
   ```

   اگر دیتابیس مقصد داده دارد، بازیابی متوقف می‌شود؛ دادهٔ موجود بازنویسی نمی‌شود. برای انتقال، `DB_FILE` یک فایل تازه باشد. نشست‌های فعال مرورگر منتقل نمی‌شوند؛ دوباره وارد شو.
4. ورود مستقل، داده‌ها و اتصال دامنه را در هاست مقصد بررسی کن و سپس دامنهٔ اصلی را جابه‌جا کن. برنامهٔ قبلی خودکار حذف یا خاموش نمی‌شود.

داده‌هایی که **فقط در Convex قبلی** مانده‌اند، بدون خروجی آن سرویس قابل انتقال نیستند. با حذف وابستگی، دادهٔ دوردست خودبه‌خود کپی نمی‌شود. برای دفتر مالی، ابزار واردکردن JSON/JSONL در پنل آماده است؛ فیلد `amountToman` باید واقعاً به تومان باشد. واردکردن تکراری یک سند، تراکنش دیگری نمی‌سازد. رمزهای قدیمی آن سرویس منتقل نمی‌شوند؛ مالک برای مشتریان رمز مستقل جدید تعیین می‌کند. بازیابی کامل JSON، داده‌های ذخیره‌شده در همین سایت را پوشش می‌دهد.

## پشتیبان‌گیری و نگهداری

```bash
npm run backup
```

این دستور از SQLite یک snapshot سازگار می‌گیرد؛ فایل‌های `-wal` و `-shm` را جدا و هنگام نوشتن کپی نکن. نسخه‌های پشتیبان، `.env` و پوشهٔ `data` خارج از وب عمومی نگهداری شوند. فایل SQLite و کد راه‌اندازی با مجوز خصوصی ایجاد می‌شوند. مقدار `DB_FILE` باید روی دیسک پایدار باشد و برای مقیاس فعلی یک نمونهٔ برنامه کافی است. پشتیبان وب برای هر جدول حداکثر ۱۰هزار ردیف را می‌پذیرد؛ برای داده‌های بزرگ‌تر از snapshot خود SQLite استفاده کن. هیچ داده‌ای بی‌صدا از خروجی حذف نمی‌شود.

هش رمزها PBKDF2-SHA256 با نمک یکتا است؛ نسخهٔ لینوکس به‌صورت پیش‌فرض ۶۰۰هزار دور استفاده می‌کند و هش‌های منتقل‌شدهٔ سبک‌تر را در ورود موفق ارتقا می‌دهد. نشست‌ها در دیتابیس به‌صورت هش ذخیره می‌شوند و cookie آن‌ها HttpOnly و SameSite است. HTTPS برای محیط واقعی لازم است. حسابداری و درخواست‌های کاربران در سمت سرور بر اساس عضویت و مجوز همان کافی‌نت بررسی می‌شوند.

## قابلیت‌های متصل‌نشده

پرداخت و تمدید همچنان دستی و از تلگرام `@Cafenetyarr`، با پلن یک‌ماههٔ ۵۰۰هزار تومان است. پیامک متصل نشده است. دستیار محلی نرخ‌ها را محاسبه می‌کند و در منابع ذخیره‌شده جست‌وجو می‌کند؛ مدل تولید متن خارجی متصل نیست و پاسخ زندهٔ اینترنتی ادعا نمی‌شود.

## ساخت از کد گیت‌هاب

```bash
npm run setup
npm run build
npm test
npm run package:linux
```

خروجی مستقل در `dist/linux` و فایل ZIP در `dist/releases` ساخته می‌شود. بستهٔ زمان اجرا به `node_modules`، ابزار build، Convex یا Cloudflare نیاز ندارد. میزبانی فعلی Sites برای پیش‌نمایش همان منطق را با D1 اجرا می‌کند؛ بستهٔ لینوکس، SQLite خود سرور را استفاده می‌کند.

## دریافت فایل از میزبانی فعلی

بستهٔ نصب از مسیر مخصوص و با لینک دارای کلید خصوصی نیز قابل دریافت است. این دانلود همان ZIP اصلی نصب است و به ورود گیت‌هاب یا لینک فایل موقت چت وابسته نیست. اعتبار لینک در تنظیمات همان میزبانی تعیین می‌شود؛ بدون کلید، دانلود مجاز نیست. این قابلیت فقط در Worker میزبانی فعلی بسته‌بندی می‌شود و فایل نصب لینوکس به آن وابسته نیست.
